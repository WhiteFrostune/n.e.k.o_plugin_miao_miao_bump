# 第三阶段：普通碰撞与水面反馈

用户选择先完成特效，备战、选人、选图与结算 UI 留到第四阶段。按用户最新要求，本阶段增加第四步“水面动态”：除了角色身后的水迹，池水本身也要有变化。本阶段按四步及用户指定顺序接入实战。用户已反馈第二步看不清，明确先推进第三步，第二步留到第四步结合水面动态一起验证，不把它标为视觉通过。

1. **普通撞击反馈（用户已认可）**：撞猫、撞墙的方向性挤压回弹、水花和短水纹；轻碰小幅、重撞明显。
2. **移动水迹（可读性待验证，留到第四步联合验收）**：滑行尾流和涟漪随速度、方向及反弹变化，减速后自然散开；用户反馈当前看不清，未获视觉认可。
3. **连撞与衔接整理（本地检查完成）**：快速再碰反馈、密集接触叠加、特效开销及淘汰／复归衔接，暂停、重开与清理。
4. **水面动态与整阶段收尾（新增，未开始）**：现有水图作为底色，补局部流动、缓慢变化的水光与少量反光，协调角色扰动和已有水迹；实机确认动态强度，再检查整个阶段的效果叠加、暂停及开销。

## 新增第四步的设计方向

用户指出，仅有移动轨迹、池水仍为静态贴图，整体观感不够融合。因此将池水本身的动态单独验收，不把它视为第二步已经完成的内容。

- 延续当前清爽像素水面，在局部加入轻微、不规则的水纹明暗变化和零星反光，使静止时也有池水的生气。
- 角色经过、碰撞或入水时，将附近的局部扰动与尾流、涟漪衔接，维持水体与角色表现的一致性。
- 保留原图备用；动态层与底图、池沿、角色和碰撞几何分开，未来地图可配置水色、强度及是否启用。
- 避免整张底图持续平移、全池同时闪烁或密集重复花纹；用户此前曾反馈水面动态有不适感，优先用温和的局部变化。
- 先做实机水面样板确认观感；尊重简化动态和暂停，控制动态区域与绘制开销，必要时回退静态水面。
- 结合用户“第二步看不清”的反馈，一起检查尾流、涟漪和底图的对比与融合；第二步的视觉验收留在这里，不单独反复调亮水迹。

以上是第四步的目标；当前水面循环样板进展见文末。第四阶段仍是备战与 UI。

## 第一步实现

- `contact-feedback.js` 是独立的纯采样模块：根据真实碰撞速度和轴向，给出压缩、回弹、恢复及分层水花／短水纹。三只角色和新旧素材共用，不新增或覆盖角色图片。
- 挤压沿真实圈心连线或墙面法线，约 18ms 达到压缩峰值，约 100ms 回弹，340ms 内恢复。幅度随碰撞法向速度变化，擦碰与重撞不同；表达不对实体施加额外力。
- 撞猫时水滴向接触两侧散开，撞墙时朝池内散开。复用第二阶段的像素水花绘制器；后层先画，前层按接触点和猫猫的前后顺序穿插，水域裁切保护池沿和界面。
- 普通接触保持正常速度及全场镜头；致命接触由已认可的淘汰演出处理，不重复叠加普通水花。
- 物理层新增独立的只读视觉事件流，包含碰撞点、圈心和碰撞时刻。低于原 65px/s 明显碰撞阈值的真实接触也能得到小幅反馈；原碰撞计数、音效过滤、伤害、回合、积分、阻力与弹性计算不变。
- 事件按真实物理接触触发，接触后在同一显示帧已走过的时间由仿真时刻补齐。后续与场景时钟一起推进，暂停冻结。新出手、重开、切换玩法及销毁清理特效。
- 同时保留的普通水花最多 20 组。简化动态保留短水纹与表情，没有挤压、晃动和喷溅；中途切简化会清理已有完整效果。

## 第二步实现

- 用独立的 `water-wake.js` 存储水迹历史和采样，`water-wake-renderer.js` 绘制短像素水线及间隔出现的后向涟漪。三只角色、新旧素材、对战与练习共用；背景水面和猫猫图片不重绘。
- 水迹按实际走过的距离生成，速度影响间隔、幅度、亮度和消散时长；低于 30px/s 不继续产生水迹。相同匀速路径在 30／60／144Hz 的位置、年龄和透明度一致。
- 水迹留在实际经过的位置，原方向保持不变；反弹或明显转向从新方向继续，不用连线跨过转折或瞬移。每只角色可见尾段最多约 240 世界单位，同时保存最多 128 个水迹标记。
- 停止或淘汰后停止新增，已有水迹自然散开；新一发重置采样起点但保留尚未散尽的水纹。入场角色不产生滑行尾流，复归不跨地图连接旧位置。
- 水迹使用与碰撞、移动一致的场景时间，停顿及慢动作时跟随，暂停时冻结；零时间推进不改变采样余量。重开、模式切换和销毁清空，简化动态不产生移动水迹。
- 所有水迹在角色及界面下方绘制，并按当前地图实际水域裁切。不影响碰撞体、阻力、发射、伤害、计分或回合等待。

## 第三步实现与检查

本轮按用户要求先完成连撞整理，未调整第二步水迹的亮度或密度，也未开始第四步水面动态。

修正了实际复现的问题：

- 两圈分开后，经近墙反弹约 8ms 再次真实接触，规则层原本正常扣血，但旧的 75ms 视觉间隔漏掉第二次反馈。现在圈间接触依靠原有空间分离判定，每次真实再碰都交给表现层；墙面仍独立过滤抖动，不改变原碰撞计数和伤害规则。
- 55ms 内跟进的轻碰会保留身体正在进行的较强挤压，避免密集接触由最后一个小碰撞覆盖主要受力表现；较强或较晚的新撞击仍能正常触发。
- 同类水花在相近位置、35ms 内合成一组局部喷溅，以较强者为准；撞墙的朝内喷溅单独保留。角色受击仍按各自真实接触处理。
- 普通水花保持最多 20 组，水迹保持最多 128 个，未消费的物理视觉事件最多 256 条。销毁页面时补齐旧水花、伤害提示、反应和物理接触队列的清理。

验证：

- Node 的连撞新增检查通过：近墙真实再碰两次均产生视觉事件，原高速度计数仍按旧规则过滤；弱接触不覆盖主要受力；局部水花合并保持方向、独立事件和数量上限，且不改输入。19 项 pytest（含全套 130 项 Node 包装）通过。
- `tests/contact_chain_browser_checks.py` 在 Edge 1600×900 通过四组检查：近墙快速再碰、一次真实连锁推动六猫、三次实际致命碰撞的镜头与下一轮复归、六物体同时运动的受控负载与完整清理。
- 快速再碰按原规则连续扣除两次 24 点血量，没有改变积分。三猫连续淘汰继续使用原镜头调度，暂停冻结后正常续播，再经规则层复归事件返回；没有旧喷溅、跨场尾迹或重复计分。
- 在该次 Edge 无界面测试中，六猫连锁的模拟与绘制回调 P95 为 1.3ms，六物体负载为 1.2ms；观测峰值为 12 组普通水花、57 个水迹标记。该数字只代表本机受控回调计时，排除截图及快照序列化，不是显示器帧率或其他设备的性能保证。
- 普通轻重碰撞、上下遮挡、撞墙、简化动画、夏日池／测试方形池的复归、血条头像、最后一分、暂停及重开回归通过，未记录页面错误。水花和水迹在角色下层或正确前后层绘制；密集伤害数字的避让仍按后续“伤害与技能表现”阶段处理。

证据位于忽略目录 `tests/artifacts/contact-chain-1/`。连锁布阵及负载属于受控检查场景，碰撞与伤害由实际物理引擎产生；不是自然整局验收。第二步可读性仍留第四步联合验收，本阶段尚未整体完成。没有提交、推送或发布。

## 第四步：可复用水面循环样板

### 水面强度第二版（待用户确认）

用户反馈第一版起伏偏小。本轮只调整夏日池配置：折射幅度由 3.2 提到 4（约 +25%），波纹尺度由 1 提到 1.15，波纹透明度由 0.44 提到 0.52；周期由 6 秒缩短到 5.5 秒（速度约 +9%）。水光密度和亮度不变。第一版参数保留在此，便于回调；原图片和复用逻辑不变。实机及录屏核对后仍等待用户观感确认。

用户明确希望池水有可见的动画，并能用于未来其他水池。本轮先接入夏日池的 6 秒循环：分区波纹错开出现，逐渐舒展、位移、断开并消散；底图同时局部折射，点缀少量水光。保留现有像素底图及旧池图，不重画或覆盖图片。样板已进实际对局，视觉观感及第二步尾流可读性仍待用户验收。

- `water-surface.js` 只根据地图水域、参数和场景时间采样；`water-surface-renderer.js` 负责缓存像素折射及绘制波纹，不自建计时器。
- 在各地图美术元数据的 `waterSurface.motion` 中启用 `preset: "pool-loop"`。可分别配置 `period`（4–12 秒）、`speed`、`direction`（二维方向）、`waveScale`、`waveOpacity`、`amplitude`、底色 `color`、`tint`、`crestColor`、`crestShade` 和 `glints`。周期为场景时间的 `period / speed` 秒；`speed: 0` 冻结相位。换地图仍使用该地图自己的水面图片与水域边界，无须复制动画代码；本轮不新增正式地图。
- 默认 24Hz 更新折射缓存，工作图最大 640×480；波纹区数按水域面积控制在 8–28，局部扰动最多 12 组。只在水域内绘制，池沿、角色、血条、界面和碰撞体保持独立。
- 复用已有入水、接触和移动水迹事件驱动局部扰动。暂停冻结，慢动作随场景时间推进，重开清理；系统简化动态和 `motion=reduce` 保留静态图。`water-motion=static` 可对照当前静态水面，`water=classic` 保留原图回退。

验证：137 项 Node 检查与 20 项 pytest 通过，包含循环首尾一致、接头连续、方形／纵向水域参数复用、定时缓存、失效回退及原水面 PNG 未改。Edge 1600×900 实际页面录制了 6 秒、144 帧循环；待机物理位置不变。另验证暂停恢复、真实鼠标出手产生局部扰动、首次实际碰撞仍扣 24 点血量、重开清空水迹，以及静态／旧图／简化三种回退，无页面错误。浏览器证据见 `tests/artifacts/water-loop-1/`。这不代表整个第三阶段或整局视觉验收完成；没有提交、推送或发布。
