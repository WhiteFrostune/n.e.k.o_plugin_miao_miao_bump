# 喵喵碰碰大作战

> 猫娘套泳圈，小猫满池弹。

一款以物理弹射和碰撞手感为核心的回合对战小游戏。玩家调整角度和力度，把猫猫弹出去，看她撞上对手、带动队友、借池壁反弹，最后在水的阻力下慢慢停稳。

**实现状态：`0.1.0.dev7` 已加入本机 3 对 3、攻防、三种被动、轮流行动、电脑出手和胜负重开。** 数值和平衡仍待试玩；实际参数、边界与验证见 [dev7 对战说明](BATTLE_DEV7.md)。

**当前开发目标：在已确认的碰撞手感上试玩完整对战。** [原碰撞阶段规划](ROADMAP_0.1.0.md) 保留第一步与美术接入记录；用户授权继续推进后，开发范围扩展至本文的里程碑 B，仍使用开发版本号，无正式标签。

## 1. 我们要做出什么感觉

这款游戏首先要让人享受到：把猫猫弹出去，看她们相互碰撞、借池壁反弹，撞来弹去的乐趣。

玩家可以认真计算角度和力度，也可以随手发射，看猫猫们撞成一团。技能和攻防规则为碰撞增加变化，但即使关掉伤害和胜负，在水池里反复发射也应该很好玩。

一次理想的出手：

1. 选中猫猫，拖出方向和力度。
2. 松手，泳圈带着猫猫滑出去，身后留下水纹。
3. 撞上另一只猫，两只泳圈挤压、回弹，运动传递出去。
4. 猫猫借池壁反弹，或者擦着另一只猫改变方向，再撞一次。
5. 速度逐渐下降，水纹变弱，全场自然停稳。
6. 玩家已经开始想下一发怎么弹。

**核心验收：同样一组猫，换一个角度、力度或擦边位置，就能撞出不同的乐子。**

## 2. 已确定的方向

- 名称：**喵喵碰碰大作战**。
- 主角：猫娘、小猫，整体走可爱、闹腾的方向。
- 每个角色都有技能、攻击力和血量。
- 碰撞必须稳定、清楚、有弹性，能连续弹上几次。
- 水有阻力，运动会衰减，最终停下来。
- 手感对标《豹豹碰碰大作战》的连续碰撞体验；具体参数通过试玩调节。

以下场景、阵容和数值属于第一版提案，可以调整。

## 3. 场景与角色表现

本节描述完整美术方向。当前三人均有暂用的待机、受撞、回弹三种像素表情和泳圈挤压反馈，像素水池已接入；朝向、浮水姿态与完整动画后续再精修。

第一版采用俯视角的夏日充气水池。四周是可反弹的充气池壁，猫猫坐在泳圈里，猫耳、头发和尾巴露在外面。

先用泳圈颜色、发色、表情和体型区分角色；双方再通过清晰的队伍标记区分，不能只靠颜色辨认敌我。

碰撞表现优先做：

- 泳圈沿撞击方向短暂挤压，再恢复形状。
- 猫耳、头发和尾巴跟着晃动。
- 发射、撞猫、撞墙分别有清楚的水纹、水花和声音反馈。
- 重撞和轻蹭有不同的表现强度。
- 受伤时短暂变表情，血量归零时进入晕乎乎的败退状态。

身体挤压是视觉反馈，基础碰撞先用稳定的圆形刚体，不要求第一版实现真实软体物理。

## 4. 物理手感目标

采用偏轻快的街机水面滑行。方向和力度决定发射，质量决定碰撞时的运动传递，弹性决定反弹程度，水阻负责让运动自然衰减。

| 操作或状态 | 第一轮调试目标 |
| --- | --- |
| 小力度 | 轻推附近的猫，能调整位置，也能进行近距离攻击 |
| 中力度 | 命中后仍有余力，产生一两次明显的后续碰撞 |
| 大力度 | 在合适的路线下，产生约 3～5 次明显碰撞，包含撞猫和撞墙 |
| 运动后半程 | 速度逐渐下降，仍能看清路径和运动传递 |
| 接近静止 | 消除没有观赏意义的缓慢爬行、抖动和反复微碰 |
| 一次行动 | 通常约 4～7 秒完成；实际时长随布局变化 |

这些是手感目标，不是每次发射必达的承诺。大力度沿空旷路线发射，也不保证发生多次碰撞。

### 衰减原则

- 不硬性限制碰撞次数。
- 滑行时持续损失速度，碰撞时也损失一部分动能。
- 保留足够弹性，让一发能连续弹几次。
- 全场速度低于停稳阈值并保持一小段时间后，结束行动。
- 异常超时可以有保护，但不能依靠定时强停制造正常手感。

### 稳定性要求

- 使用固定物理步长，避免不同显示帧率改变手感。
- 高速发射不能穿过猫猫或池壁。
- 多只猫拥挤时不能严重重叠、持续抖动或凭空加速。
- 墙角和贴墙碰撞要稳定。
- 切换页面或短暂卡顿后，不能补算出一发失控的超大位移。
- 视觉泳圈和实际碰撞范围应基本一致。

第一版重点调水阻、弹性和质量，让橘子的分量、布丁的反弹都能从运动中直接看出来。

## 5. 第一版对战流程

一个固定水池，玩家对电脑，双方各三只猫，轮流行动。第一版由玩家先手，双方使用相同的角色组合。

1. 选择己方一只尚未败退的猫。
2. 拖拽调整方向和力度；取消拖拽可以重新选择。
3. 松手发射，进入物理演算阶段，暂时不能再次发射。
4. 碰撞过程中即时显示伤害、技能反馈和血量变化。
5. 全场停稳，处理败退离场，检查胜负。
6. 若比赛继续，交换行动方。

己方猫全部败退则失败，敌方猫全部败退则胜利。结束后可以直接重开。

### 瞄准与操作

- 显示发射方向，拖拽距离决定强弱；按用户要求不再显示独立力度条或数值。
- 瞄准线先提示初始方向；若先碰到池壁，再提示第一次反射方向。
- 若先碰到猫，预览停在首次接触处，不穿过猫继续画出误导路径。
- 第一版不预演整场连锁，也不显示精确伤害预测。
- 优先支持鼠标，同时保留触摸拖拽的操作方式。

### 血量展示

血量和血条同时保留：头顶显示短血条，选中时显示当前／最大血量、攻击力和技能说明。受击时显示伤害数字。

## 6. 第一版角色提案

每只猫先有一个自动生效的专属技能，让差异直接体现在碰撞中。初始名称和数值均可调整。

三人共用悠怡 PNGTuber 的大头短身、圆脸和猫耳造型语言，转换为有清楚像素颗粒的游戏美术。悠怡保持独立角色身份。

| 角色 | 原型猫 | 外形方向 | 头顶小猫与泳圈 |
| --- | --- | --- | --- |
| 橘子 | 中华田园橘猫，采用橘色虎斑 | 橘色外翘短发、琥珀眼睛、条纹尾巴 | 小橘猫；橘瓣泳圈 |
| 布丁 | 海豹重点色暹罗猫 | 奶油色头发、深棕发尾、双团子、蓝眼睛 | 小暹罗；焦糖布丁泳圈 |
| 奶盖 | 蓝双色布偶猫 | 奶白蓬松长发、灰蓝耳尖、蓝眼睛、大毛尾 | 小布偶；淡紫软垫泳圈 |

三人的暂用像素图集和头顶小猫已接入；泳圈仍由代码绘制，颜色和外缘与碰撞范围一致。

| 角色 | 血量 | 攻击力 | 技能 | 体验目标 |
| --- | ---: | ---: | --- | --- |
| 橘子 | 120 | 24 | **沉甸甸**：质量更大，更难被撞走 | 撞击有分量，能推开猫群 |
| 布丁 | 85 | 18 | **超弹泳圈**：撞墙时损失更少的动能 | 借池壁连续反弹，寻找绕行路线 |
| 奶盖 | 100 | 20 | **软垫护护**：每次敌方行动中，首次受到的有效攻击减少 8 点伤害 | 能承受第一撞，防护反馈清楚 |

质量变化必须保持物理一致性，不能同时无条件获得更强推力、更高速度和更强抗撞。各角色的发射响应需要一起调试。

先不增加主动技能按钮、冷却或能量系统。第一版先验证三只猫是否已经撞起来不一样。

## 7. 伤害与碰撞规则

第一版优先让规则清楚、可预测。

- 当前行动方的猫撞到敌方猫，才能造成攻击伤害；该行动中敌方不会因普通碰撞自动反击。
- 队友之间不扣血，但正常传递运动。
- 被撞动的己方队友也能撞伤敌人，伤害使用这只队友自己的攻击力。
- 敌方猫互相碰撞只传递运动，不额外扣血。
- 普通撞墙不扣血。
- 达到最低有效撞击速度才触发伤害；使用接触前、沿碰撞方向的相对速度判断，慢蹭不算攻击。
- 基础伤害先使用攻击力，再应用减伤等技能。力度主要影响距离和碰撞机会，第一版不直接按速度放大伤害。

### 连续碰撞与重复扣血

两只猫持续贴在一起，只算一次接触，不会每个物理帧都扣血。

只有明确分离后重新撞上，且重新达到有效撞击速度，才可能再次造成伤害。需要过滤接触抖动，避免墙角挤压刷伤害，同时保留真正来回反弹的连续攻击。

### 败退处理

血量归零后立即失去攻击和技能能力，也不能再次被选择发射。身体保留正常碰撞到本次行动结束，再播放离场表现，避免突然消失改变正在发生的路线。

## 8. 两个开发里程碑

### A：先把碰撞场做舒服

提供练习模式，使用和正式对战相同的物理实现。

- 可以反复发射、重置布局。
- 有单猫撞墙、两猫对撞、擦边、多人连撞、墙角拥挤等测试布局。
- 可以在调试区调整水阻、弹性、质量和发射强度。
- 练习模式可以关闭伤害，专心感受弹射。
- 能验证大小力度区别、连续反弹和自然停稳。

**通过条件：不靠技能或胜负奖励，单纯发射猫猫也愿意反复玩。**

### B：完成第一版对战

在同一套碰撞实现上加入：

- 玩家对电脑的 3 对 3。
- 三种角色及各自技能。
- 攻击力、血量和有效碰撞伤害。
- 选中、瞄准、发射、演算、换边、胜负和重开。
- 基础水花、泳圈挤压、表情和音效。
- 简单电脑出手：选择己方猫，尝试若干角度和力度，优先命中对手。

电脑使用本地规则即可。核心玩法不依赖模型调用，发射后也不需要等待网络返回。

**通过条件：能从开局连续玩到胜负，轮次清楚，伤害不乱跳，运动稳定，结束后愿意再开一局。**

## 9. 第一版暂不包含

- 抽卡、养成、装备和经济系统。
- 祝福三选一、关卡地图和长线肉鸽流程。
- 大量角色、主动技能和复杂状态效果。
- 漩涡、水流、机关和可破坏场景。
- 完整剧情、配音和复杂角色动画。

| 展示名称 | 喵喵碰碰大作战 |
| 插件 ID | `miao_miao_bump` |
| 包类型 | 独立 `plugin` |
| 正式工作目录 | `plugin/plugins/miao_miao_bump/` |
| 主入口 | `plugin.plugins.miao_miao_bump:MiaoMiaoBumpPlugin` |
| 游戏前端 | Canvas + Matter.js，游戏循环在浏览器运行 |
| Python 职责 | 插件生命周期、必要的设置和存档入口 |
| 游戏界面 | 独立 Static UI，容纳游戏引擎脚本、资源和完整渲染循环 |
| 普通管理界面 | 需要时使用 Hosted TSX |

静态游戏界面的选择基于独立引擎脚本和资源加载需求：当前 Hosted TSX 禁止直接导入 npm 包，采用受限运行环境。具体资源路由、设置与存档通信在实现前按公开 SDK 核对。

正式创建时使用项目标准 CLI 生成骨架，随后将实现与资源保留在插件目录中。使用公开 SDK、异步运行入口和插件自有国际化文本；资源采用可分发的原创或已获授权素材，依赖保留许可证。

本文是整体设计草案。当前已有可玩的占位泳圈碰撞练习场，正式美术、角色技能和完整对战尚未实现。

## 11. 第一版验收清单

- [ ] 小、中、大力度有明确区别，拖拽和发射方向一致。
- [ ] 合适路线下能连续弹几次，不只发生一次撞击就停。
- [ ] 运动逐渐衰减，最终可靠停稳。
- [ ] 正面、擦边、撞墙和连撞的结果容易看懂。
- [ ] 橘子、布丁和奶盖有可感知的差异。
- [ ] 队友之间传递运动，被带动的队友可以参与攻击。
- [ ] 贴靠和抖动不会重复刷伤害，真正分离再撞可以再次攻击。
- [ ] 高速、墙角、拥挤和页面暂停恢复不会破坏物理稳定性。
- [ ] 玩家与电脑可以正常交替行动，完成胜负并重开。
- [ ] 画面能清楚辨认敌我、当前行动方、血量和技能触发。

**最终判断：先问“撞起来爽不爽”，再问“还能加什么”。**
