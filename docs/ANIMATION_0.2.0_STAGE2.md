# 第二阶段：入场与复归入水

按小步实战验收推进，各步完成后由用户确认，再扩展。

## 第一步：橘子的入场动作（用户已认可）

开场与淘汰后的复归共用同一套独立表现：空泳圈先从己方池边入场，角色斜扑、撑圈下沉，再回浮待机。橘子的两张补绘姿态来自用户认可的样图；头顶小猫随主体运动。待机、旧版角色、泳圈与淘汰素材保留。

动画由素材、纯运动采样和对局入口组成。开场与真实 `respawn` 事件共用 `beginEntrance`；以复归逻辑实际选出的安全位置为落点，不覆盖出生点或其他角色。电脑等角色落稳后才出手，玩家开始操作可跳过剩余入场。减少动态模式或可选素材加载失败时正常回退。

## 第二步：橘子的入水水花和水纹（用户已认可）

- 在 `LANDING.touch` 的撑圈接触时刻溅起局部像素水滴，先向外上方散开、再下落消隐；入场途中不提前溅水。
- 水滴分前后层，水纹在角色下方扩散，避免遮住脸与头顶小猫。水纹在身体回浮结束后短暂散尽，不延长电脑的等待。
- `landing-water.js` 负责可复用的纯采样，`landing-water-renderer.js` 负责像素绘制。坐标、半径和年龄来自实际入场，与物理、伤害、计分及复归时机分开。
- 背景水面和第一步动作不重绘。开场、复归共享；本步先用于橘子。
- 所有水花限制在实际地图水域。暂停冻结；重开、切模式、减少动态效果、开始出手和销毁会清理，不把旧落点水花带到新对局。

## 第三步：布丁与奶盖复用入场（用户已认可）

- 用内置 image_gen 参照橘子已认可的动作补出两张角色图集，各含空圈、斜扑和撑圈姿势。布丁保留黄白细肩带蝴蝶结款及暹罗小猫，奶盖保留淡紫白单肩小花款及灰白小猫；均为分体泳装、无领无袖、赤脚。绘图提示及参考记录在 `docs/art/trio-entrance-v1-prompts.json`。
- 素材保存于 `static/assets/characters/opening-v1/{pudding,milkcap}.{json,png}`，角色元数据通过可选 `opening` 字段加载；没有覆盖原待机、头像和淘汰图片。
- 复用现有运动采样、水花采样、渲染和 `beginEntrance`，没有为另外两只猫复制动画机制。开场六名角色轻微错开，角色间隔 60ms、两方间隔 90ms；复归直接使用实际安全落点。
- 电脑继续等待全部入场动作结束，水纹尾段不增加等待。减少动态、缺图回退、暂停、重开与切换玩法继续共用清理流程。

## 收尾：界面状态与生命周期（本地检查通过）

用户认可三猫表现后完成本轮收尾，第二阶段本地开发完成，下一阶段是普通碰撞与水面反馈。没有提交、推送或发布。

- 修正还在入场时已经显示普通回合／可出手提示的问题：顶部显示“猫猫入场中”，入场角色保持彩色头像并带蓝色省略号；落稳后自动恢复角色原有状态。已行动仍用勾，淘汰待复归仍用灰色及叉。
- 头像提示、无障碍说明与侧栏状态共用角色状态来源。复归 HP 以规则层恢复后的实际数值为准；场内血条在角色入场结束后出现。不会因水纹结束再次加血或改变机会。
- 保留主动拖拽跳过剩余入场；取消瞄准不会消耗机会。电脑等待入场动作结束，但不等待尾纹完全消散。没有改变动画姿势、轨迹或伤害、积分、复归规则。
- 暂停时入场和水花都冻结；重开替换旧轨迹；切换玩法及简化动态清理相关表现。最后一分等待淘汰演出结束才显示结果，不启动多余复归。
