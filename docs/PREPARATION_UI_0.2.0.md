# 对战流程 UI：备战、阵容、地图与结算

## 优先级

第三阶段收尾后，按已绘制的全流程概念图推进第四阶段。每次交付一个可单独预览的界面，当前界面通过验收后再做下一页。选猫页另有一张放大概念图，用于确定动作舞台和阵容栏的比例。

本文件是设计与实施规划，不代表这些页面或选人机制已经实现。阶段开发不自动提交、推送或发布。

## 一轮游戏的流程

打开游戏进入备战 → 选择三猫阵容与地图 → 开始对战 → 胜利／失败／平局结算 → 同配置再来一局或返回备战调整。

备战作为主页面，不必先叠一层只有“开始游戏”的菜单。角色和地图选择是备战中的两个部分，可以打开各自的选择面板，避免三个完整页面反复跳转。

## 备战与角色选择

- 首次进入备战时，我方三个出战位为空。水面近景里的三个空泳圈各有「＋」，点击对应站位打开选猫页。大厅同时显示当前地图、对手和开始按钮。
- 从泳圈进入选猫页，按点击头像的顺序分配 1、2、3 号位。再点已上阵的头像就取消选择，后面的编号自动前移。选满三只后确认整队，回大厅按编号入位。退出时保留上次确认的阵容。
- 赛后返回备战时保留这次选好的阵容和地图，方便换位或再次开战。
- 4.2 先用现有角色静态图预览。以后可在同一舞台接上招牌动作和重播。橘子可演示受撞后稳住，布丁可演示贴墙回弹，奶盖可演示软垫接下首撞。浏览猫猫和确认阵容分开。
- 初版沿用橘子、布丁、奶盖，三猫出战且不重复；可以调整谁在三个栏位中的哪个位置。以后角色增加后，同样从角色列表挑三只，不重做整页。
- 栏位对应所选地图的预设出生位置。地图预览标出队伍位置，避免选人顺序和实际站位对不上。
- 开战前展示明确的完整阵容；缺少角色、重复角色或无效地图时给出可理解的提示。
- 对手暂时仍由本机逻辑控制，沿用当前名字设置；未来猫娘接管属于独立扩展，不在这一步接入模型。

## 地图选择

- 大厅在「开始对战」左边提供独立的「选择地图」按钮，上方地图牌显示当前地图。游玩版目前只列出夏日水池。
- 每张真实可玩的地图以预览图、名称、场地形状和已实现的规则说明组成卡片。
- 当前正式地图只有夏日水池，先接这张真实地图；不把测试地图或未实现的草图当作可玩内容。
- 选择信息由现有地图注册表提供。预览复用对局池面和出生坐标。新地图注册后自动加入列表，优先补上空白模板的位置。
- 地图选中状态在备战中可见；选择过程不提前创建对局。按“开始对战”才使用确认后的阵容与地图。

## 结算画面

- 胜利、失败和平局分别有清楚的标题与配色，显示双方最终比分、出战阵容、所用地图和本局轮次。
- 沿用现有可爱像素美术，角色展示使用适当的立绘／头像素材，保证比例和留白，不把场内小图任意拉伸充当大立绘。
- 主要操作为“再来一局”和“返回备战”：前者保留地图与阵容并干净重开，后者保留当前选择以便修改。
- 最后一分仍在淘汰演出完成后结算，不能提早盖住击飞；离开对局、重开或返回备战时清理镜头、入场、水花和旧的电脑操作。
- 本轮不引入货币、经验、抽取、战利品等额外系统。

## 为扩展做的必要调整

角色选择不能只在 UI 换头像。目前角色身份依赖角色编号对 3 取余，复归位置也使用角色类型索引；需要区分“角色是谁”和“角色在队伍中的哪个栏位”。

- 角色资料：稳定角色标识、名称、头像、泳装／入场／淘汰素材、数值和技能资料。
- 队伍资料：三猫的角色标识与栏位顺序；实际绘图、技能、血量读取该角色的资料。
- 地图资料：继续使用已存在的地图定义和每队三个出生点，按队伍栏位分配出生及复归位置。
- 对局配置：当前地图、双方阵容和原有规则配置。备战确认后生成一个新对局。
- 界面流程：备战、对局、结算各自有明确状态；返回和重开不依赖旧对局是否仍在播放动画。

不借这次 UI 调整改动伤害归属、每轮机会、积分规则、已认可的动画轨迹或角色数值。

## 分步推进

| 步骤 | 单独交付的界面 | 验收时看什么 |
| --- | --- | --- |
| 4.1 备战大厅 | 夏日水池近景、三个空泳圈与「＋」、对手、地图和开战入口。先独立预览初始空阵容和待开战状态。 | 玩家一眼能看出从哪里选猫、还缺几只。三个位都好辨认，标题和按钮在常见桌面窗口里有足够空间。 |
| 4.2 选择猫猫 | 接通空泳圈的选猫入口。左侧头像卡的左上角显示上阵编号，右侧是静态大图、数值、特性和整队确认。 | 选到两只时只有两张卡有编号。再次点头像会取消选择，剩余编号自动前移。确认后，三只猫按编号回到大厅泳圈。 |
| 4.3 选择地图 | 夏日水池的俯视预览、场地说明、双方各三个编号出生点。 | 地图标记与真实出生点一致，队伍和栏位能对上。确认后，大厅显示所选地图。 |
| 4.4 开场对阵 | 在已准备好的俯视池面上，蓝红横幅滑入、中央亮出 VS，1.6 秒后接入水。 | 两边身份清楚，转场收尾与入水第一帧连贯。简化动态直接进池。 |
| 4.5 对局 HUD | 把已确认的阵容和地图接到现有对局的头像、轮次、比分与角色信息。 | 调换站位后，猫猫的头像、数值、特性、出生和复归位置一致。拖拽瞄准时池面和血条清楚。 |
| 4.6 胜负结算 | 最后一击后先显示最终比分，再进入三猫展示。覆盖胜利、失败和平局，并提供再来一局、返回备战。 | 比分与出战阵容正确。再来一局沿用配置，返回后还能继续调整。 |
| 4.7 串联验收 | 从大厅出发，完成选猫、选地图、开战、结算和下一局。 | 实玩连续两局，核对中途返回、重开、最后一分、暂停、常见桌面尺寸与语言。 |

先用现有三角色及夏日水池把完整流程做通，新角色、新地图内容仍另行规划。

4.1 和 4.2 共用备战大厅 `static/preparation.html`。首次打开时显示我方三个空泳圈，点「＋」打开选猫面板。池景使用 `summer-pool-lobby-v1.png`，泳圈和猫猫复用原有美术。

选猫界面参考[崩铁小组赛选豹页约 0:41](https://www.bilibili.com/video/BV1mHdmYbEQn/?p=2&t=41)。左侧横排头像卡标出角色所在站位，右侧先看角色大图，再看数值、特性和确认操作。

角色列表从现有对战角色表和本地化资料生成，阵容槽保存角色标识。新增角色时补上角色资料、文案和美术，列表随之扩展，出战位仍为三个。静态图由独立的预览函数绘制，后续可按角色接入动作。

4.4 已接通开场对阵。真实池面绘制完成后播放蓝红横幅与水纹 VS。约 0.48 秒滑入并亮相，0.88 秒完整展示双方阵容和 VS，0.24 秒退场，接着播放六猫入水。简化动态直接进入池面。参考实录约 0:45.1 可见横幅滑入，0:45.7 至 0:46.3 双方头像与 VS 清楚可见，0:46.6 已切至抛硬币。[崩铁小组赛实录](https://www.bilibili.com/video/BV1mHdmYbEQn/?p=2&t=44)

4.5 已完成本地验收。从空阵容按奶盖、橘子、布丁的顺序选猫，确认夏日水池后开战，顶部头像、场内站位和左侧角色信息均按新顺序显示。实战拖拽出手后，对应头像显示本轮已行动。另用方形测试地图验证一号位奶盖被淘汰后，对方加一分，奶盖下一轮满血回到一号位。下一步为 4.6 胜负结算。

4.6 已接入实战。最终击飞结束、比分确定后，先在池面亮出蓝红大比分，约 1.2 秒后开始淡入结算舞台。结算保留最终比分、地图、轮次和玩家本局的三只出战猫。胜利、失败和平局各有标题及配色，简化动态直接显示结算舞台。再开一局沿用地图与阵容，返回备战保留双方站位和所选地图。参考实录约 12:26 的池面比分、12:29 的三豹胜利舞台。[崩铁小组赛实录](https://www.bilibili.com/video/BV1mHdmYbEQn/?p=2&t=744)

整轮结束进入下一轮时，池面短暂提示新轮次及双方累计淘汰数。提示自动消失，玩家也可以直接拖拽出手。

4.7 已在 Edge 串联验收。从空备战按奶盖、橘子、布丁选猫并确认夏日水池，先验证中途浏览器后退保留阵容及地图，再按正式伤害与计分规则打完两局。两局之间用结算页「再开一局」，第二局结束后用「返回备战」。两局均在第 6 轮以 3:5 结算，每局 14 次我方出手。检查覆盖中途暂停、桌面尺寸、中文和英文 HUD。

正常开局现在默认使用三猫新版泳装脱圈与对应演出，保留旧版对照入口和玩家的动画偏好。完整对局记录到橘子和布丁的新版击飞。另以受控起始位置和真实物理接触逐只验证三猫的泳圈拆分、飞行方向及一次计分，覆盖奶盖的动作。

第四阶段收尾后，插件打开备战大厅。浏览器刷新对局会回到备战并保留配置，局内重开经确认使用原阵容和地图开新局，赛后可直接再开一局。游玩版使用完整演出。旧演出、简化动画对照、测试选项及物理调试集中在 `tests/flight_fixture.py` 生成的开发验收页。地图选择只显示正式可玩的地图。
