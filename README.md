# 喵喵碰碰大作战

> 猫娘套泳圈，小猫满池弹。

一款为 [N.E.K.O](https://github.com/Project-N-E-K-O/N.E.K.O) 设计的猫娘泳圈碰撞小游戏。调整角度和力度，把猫猫弹出去，看她们相互碰撞、借池壁反弹，最后在水的阻力下自然停稳。

**作者：[WhiteFrostune](https://github.com/WhiteFrostune)**

**当前状态：可完整游玩的本机 3 对 3 对战（`0.1.0.dev7`）。** 双方各有橘子、布丁、奶盖，已加入攻击、血量、专属被动、电脑出手、轮流行动和胜负重开，保留自由练习。角色与地图美术暂用当前资源，可独立替换；平衡仍待试玩，尚无正式版本标签。

## 开始试玩

在 N.E.K.O 的插件管理器中刷新插件列表，打开本插件的「喵喵碰碰大作战」面板即可试玩；启动插件后也可点击同名游戏入口。游戏在浏览器中运行。

也可以在 N.E.K.O 仓库根目录启动独立本机预览：

```bash
uv run python -m http.server 48921 --bind 127.0.0.1 --directory plugin/plugins/miao_miao_bump
```

然后访问 [本机试玩页](http://127.0.0.1:48921/static/index.html?locale=zh-CN)。预览服务运行期间可以访问，停止后链接不再可用。

默认进入 3 对 3：◆ 为我方，● 为电脑。玩家先手，按住己方猫猫或泳圈向后拖拽，松手发射；Esc 或右键取消。有效撞击扣血，全场停稳后换边，电脑会自动出手；敌方全部败退即获胜，可直接再开一局。

底栏可切到「自由练习」，无伤害和被动，可选撞墙、对撞、连撞、墙角布局，并调整水阻、弹性、速度和质量。对战使用固定参数，练习调参不会带入对战。

| 角色 | 血量 | 攻击 | 被动 |
| --- | ---: | ---: | --- |
| 橘子 | 120 | 24 | 沉甸甸：更重，起步稍慢，更难被撞走 |
| 布丁 | 85 | 18 | 超弹泳圈：撞墙保留更多速度 |
| 奶盖 | 100 | 20 | 软垫护护：每次敌方行动的首击减伤 8 |

队友只传递运动，不互相伤害；被带动的队友也能攻击。低速轻蹭不扣血，持续贴住不会反复刷伤害；败退的猫猫等一发停稳后再离场。完整数值和边界见 [对战说明](docs/BATTLE_DEV7.md)。

## 角色与美术方向

![橘子、布丁和奶盖的像素概念图](docs/art/character-concepts.png)

| 角色 | 原型猫 | 外形与配饰 |
| --- | --- | --- |
| 橘子 | 中华田园橘猫，橘色虎斑 | 橘色外翘短发、琥珀眼睛、条纹尾巴；头顶小橘猫，橘瓣泳圈 |
| 布丁 | 海豹重点色暹罗猫 | 奶油色头发、深棕发尾、双团子、蓝眼睛；头顶小暹罗，焦糖布丁泳圈 |
| 奶盖 | 蓝双色布偶猫 | 奶白蓬松长发、灰蓝耳尖、蓝眼睛、大毛尾；头顶小布偶，淡紫软垫泳圈 |

角色沿用悠怡 PNGTuber 的大头短身、圆脸和可爱表情语言，转换成有清楚颗粒的像素美术。悠怡是独立角色，三位新角色分别设计自己的轮廓与配色。

图中为生成式概念样板，供讨论外观与配色。三只猫的三表情和夏日像素水池均已接入游戏，当前暂用资源继续推进玩法。参考来源与替换说明见 [美术说明](docs/art/README.md)。

![本机3对3对战的实际画面](docs/art/battle-dev7.png)

水池根据窗口可用宽高等比缩放，完整地图、重开和底部操作栏留在同一屏内。底栏显示血量、攻击和被动；「角色与表情」和「调整手感」按需打开弹窗。头顶显示血条，受伤时出现伤害数字和减伤提示。界面已移除碰撞次数、用时、当前速度与力度显示。

三只猫均按 48 × 56 的游戏像素网格绘制并整块放大，泳圈半径为 40。点击可见头部或泳圈都能选择己方猫猫，实际碰撞以泳圈外缘为准。

## 当前原型包含

- 一个矩形像素水池、两组三只猫的暂用三表情图集。
- 拖拽瞄准、松手发射、取消、回合提示和重开。
- 泳圈碰撞、池壁反弹、水阻衰减和自然停稳。
- 攻击、血量、被动、伤害数字、敌我标记、电脑出手和胜负。
- 三人的头顶小猫、表情，以及泳圈挤压、水花、回弹和可关闭的本机合成音效。
- 单圈撞墙、两圈对撞、三圈连撞和墙角拥挤测试布局。
- 弹窗调参区，以及高速、缩放、页面暂停恢复等稳定性检查。

第一步碰撞手感已获试玩确认；当前重点试玩血量、伤害、被动差异、电脑难度和一局节奏。

## 开发方式

仓库遵循 N.E.K.O 独立插件约定，仓库名为 `n.e.k.o_plugin_miao_miao_bump`，插件 ID 为 `miao_miao_bump`。

克隆到本地 N.E.K.O 源码的插件目录：

```text
N.E.K.O/plugin/plugins/miao_miao_bump/
```

在 N.E.K.O 仓库根目录运行：

```bash
git clone https://github.com/WhiteFrostune/n.e.k.o_plugin_miao_miao_bump.git plugin/plugins/miao_miao_bump
uv run neko-plugin check miao_miao_bump --strict
uv run pytest plugin/plugins/miao_miao_bump/tests -q
```

目录已经存在时，使用已有检出目录继续开发。插件通过公开 SDK 接入，默认手动启动。静态游戏面板无后端调用权限，启动插件仅注册静态页面与打开入口，不会启动后台游戏任务。

当前采用 Canvas + 本地 Matter.js 0.20.0，在浏览器内完成游戏循环；游戏页面、物理引擎和资源均保留在插件目录中，游玩时不请求外部 CDN。

代码风格检查在本插件仓库根目录运行，使用与 GitHub 相同的 Ruff 版本：

```bash
uvx ruff==0.12.4 check --ignore-noqa --config ruff.toml .
```

独立仓库中的 N.E.K.O 宿主导入按外部依赖分组；检查配置将源码根目录固定为本插件目录，避免在宿主仓库内开发时产生不同的导入分类。
